# File Breakdown & Architecture Roles

## Backend Services & Python Route Handlers (Scene-First Storage)
- **`backend/routes/api.py`**
  - **Role:** Main FastAPI entry point serving the orchestration endpoints (`/api/workflow/stage`, `/api/projects`, `/api/workflows/parse`, etc). 
  - **Updates:** Now utilizes `find_asset_file_path` for unified cross-tier asset lookups when transferring resources via SSH, validating project files, or generating project export ZIP packages. Explicitly parses `scene_name` across endpoints to support the localized `assets/{scene_name}/{media_type}/` hierarchy.

- **`backend/utils/file_handlers.py`**
  - **Role:** File operations and string normalization module.
  - **Updates:** Houses the core `find_asset_file_path` resolution utility which scans active scene subdirectories before falling back to legacy flat directories. Provides `get_scene_directories` to yield fully provisioned absolute paths on demand, guaranteeing folder existence prior to writes. Implements `format_scene_folder_name` to clean untrusted metadata inputs (e.g. standardizing "Scene 1" -> "scene01").

## Node.js Express Server Middlewares (Uploads & Assets)
- **`server/config/constants.ts`**
  - **Role:** Configuration globals.
  - **Updates:** Establishes the `assets/` schema constants alongside the legacy ones, exporting dynamic lookup utilities to bind the new structures.

- **`server/services/assetService.ts`**
  - **Role:** Handles multipart form uploads (single and chunked), maintains the active registry state, and bridges frontend requests to disk storage.
  - **Updates:** Refactored `getAssetFilePath` to match Python's two-tier Scene-First resolution. Modified `handleSingleFileUpload` and `handleChunkUpload` to intercept `scene_name` metadata, dynamically calculating the destination write stream path (`assets/{scene_name}/{media_type}/{filename}`).

- **`server/routes/assetRoutes.ts`**
  - **Role:** Express route controllers for `/api/assets/*`.
  - **Updates:** `serveAssetFile` strictly pipes files using `assetService.getAssetFilePath`, granting it the ability to seamlessly serve blobs across the localized or legacy hierarchies.

- **`server/routes/workflowRoutes.ts`**
  - **Role:** Express route controllers for `/api/workflows/*`.
  - **Updates:** Extracts `scene_name` during the upload of ComfyUI JSON templates to direct them into the specific `assets/{scene_name}/workflows/` directory.

## React Frontend Components (Metadata Binding)
- **`src/App.tsx`**
  - **Role:** Main application orchestrator mounting all contextual tabs and dispatching global API queries.
  - **Updates:** Assures that `scene_name` metadata is bound and piped properly into `WorkflowSection`, `GallerySection`, and `AssetManagerSection`. Passes active `scene_name` to `/api/workflows/parse` to guarantee accurate ComfyUI JSON discovery.

- **`src/components/AssetManagerSection.tsx`**
  - **Role:** Core Shot-Level media planning panel.
  - **Updates:** Enforces explicit injection of `scene_name` into the active `FormData` payload when uploading or editing assets, confirming files are properly routed to their respective contextual folder blocks rather than an orphaned flat directory.

- **`src/components/GallerySection.tsx`**
  - **Role:** Global library browser and bulk uploader interface.
  - **Updates:** Incorporates `sceneName` fallback prop to correctly decorate `FormData` payloads during recursive batch uploads (`runBulkUpload`).

- **`src/components/WorkflowSection.tsx`**
  - **Role:** Pipeline graph manager supporting workflow staging and dynamic media overrides.
  - **Updates:** Assures uploaded ComfyUI `.json` templates submit the active `scene_name` to guarantee the template is correctly nested inside `assets/{scene_name}/workflows/`.

## Project Persistence Extensions
- **`server/services/projectService.ts`** & **`backend/routes/api.py`**
  - **Role:** Handles saving, loading, and importing `project.json` payloads.
  - **Updates:** Automatically intercepts and inspects incoming project data to extract the nested `scene_name` metadata. Invokes the `ensureSceneDirectories` subroutine to recursively provision all Scene-First storage folders immediately upon creation, saving, fetching, or importing of a project. Ensures isolated `assets/{scene_name}/*` sandboxes are physically available before media starts rolling in.

## Upload Handlers hardened
- **`backend/routes/api.py`** & **`server/services/assetService.ts`** & **`backend/utils/file_handlers.py`**
  - **Role:** Handles multipart form uploads (single and chunked), maintains the active registry state, and bridges frontend requests to disk storage.
  - **Updates:** Fixed strict dictionary lookups triggering KeyErrors when dynamically resolving scene storage blocks. Upload destinations now safely fallback using `get()` and safely handle unexpected content payloads (like generic files, workflow scripts) into `.shared` or `.images` directories rather than throwing Exceptions. Included `path` and `preview_url` properly onto all synthesized AssetRecord returns. Guaranteed `mkdir` recursive initialization right before file move actions across all single-file and chunked handlers to avoid racing conditions where the folder isn't fully staged.

## Upload Serving and UI References fixed
- **`src/components/AssetManagerSection.tsx`**, **`src/components/GallerySection.tsx`**, **`src/components/WorkflowSection.tsx`**, and **`src/App.tsx`**
  - **Role:** Handles attaching metadata (like active scene identifiers) onto UI components and HTTP forms.
  - **Updates:** Eliminated static `scene01` fallbacks. Extracted an `activeSceneName` derivation (favoring `sceneProject.scene_name`, then `currentProjectName`, then `Untitled_Scene`) in `App.tsx` and cascaded it consistently through all media components and visually into the physical storage path UI indicator.
- **`backend/routes/api.py`**
  - **Role:** Exposes Python FastAPI routes under `/api/`.
  - **Updates:** Added a dynamic file serving proxy at `GET /api/uploads/{filename}` via `FileResponse` that taps into `find_asset_file_path()`. This successfully navigates nested Scene subdirectories (e.g. `assets/*/images/`) returning 200 statuses with proper Content-Type headers, bridging the NGINX routing gap.

## Unified Asset File Resolver Integration
- **`backend/utils/file_handlers.py`**
  - **Updates:** Implemented and solidified `find_asset_file_path`, a unified asset file resolver utility. It locates any asset by filename across the entire Scene-First hierarchy (recursively scanning all scene directories under `assets/`, including `images/`, `videos/`, `audios/`, `workflows/`, `shared/`, as well as legacy flat upload locations).
- **`backend/routes/api.py`**
  - **Updates:** 
    - **Project Export (`/projects/{filename}/export`):** Updated the project ZIP export endpoint to exclusively use the unified asset file resolver. All media assets referenced within the project JSON (assets lists, assigned shot input slots, shared assets, and node mappings) are accurately discovered in their dynamic scene subfolders and successfully packed into the ZIP archive.
    - **SSH & Staging Endpoints (`/assets/sync_remote`, `/workflow/stage`, `/execute`):** Updated the SSH asset transfer, scene staging, and master execution endpoints. They now resolve local asset files using the unified file locator prior to dispatching them via SFTP to the remote ComfyUI input directory on RunPod, preventing "file not found" errors during complex staging tasks.
    - **Project Import (`/projects/import`):** Refactored the ZIP import endpoint using a two-pass mechanism. It now reads the project JSON metadata and `assets_db.json` first, determines the active scene name, provisions the correct directories via `ensure_scene_directories`, and subsequently extracts all workflows and uploads directly into their proper contextual scene subdirectories rather than indiscriminately dumping them into legacy flat folders.

## Container Mount Path Anchoring
- **`backend/utils/file_handlers.py`** & **`server/config/constants.ts`**
  - **Updates:** Re-anchored the root project asset path to explicitly use the Docker mount boundary (`/app/assets` if detected) rather than resolving relative to the `backend/utils/` subfolder. This enforces that all derived paths (`project_jsons`, `scene01`, `tmp_uploads`) strictly generate and build their Scene-First directories directly onto the mounted `/app/assets` host volume, solving missing data persistence on container restart.

## Chunked Upload Pipeline Finalization
- **`src/components/AssetManagerSection.tsx`** & **`src/components/GallerySection.tsx`**
  - **Updates:** Updated the chunked upload iterators to actively append `scene_name` to every chunk `FormData` object. This guarantees that when the final file chunk executes, the backend correctly places the fully stitched file within the `scene_name` target directory.
- **`backend/routes/api.py`** & **`server/services/assetService.ts`**
  - **Updates:** Modified the chunk assembly handler to consume the `scene_name` metadata, resolve the proper nested media directory, stitch the file into its final scene path on disk, and explicitly verify file existence via an `fs.existsSync` or `os.path.exists()` assertion prior to emitting the successful `AssetRecord` back to the frontend.

## Recursive Asset Discovery
- **`backend/utils/file_handlers.py`**
  - **Updates:** Refactored `find_asset_file_path` to implement a fully recursive search utilizing `rglob` across all directories and subdirectories underneath the base `ASSETS_DIR`. This guarantees immediate location of any asset by its filename, regardless of how deeply nested it is within `images/`, `videos/`, `workflows/`, or `shared/` under any scene folders.
- **`backend/routes/api.py`**
  - **Updates:** Hardened the asset serving endpoint `/api/uploads/{filename}` by explicitly utilizing the `mimetypes` module to extract and pass appropriate MIME type headers directly into the `FileResponse`. This ensures robust cross-browser rendering for media assets resolved by the recursive finder.

## Project Filename Sanitization & Overwrite Strategy
- **`backend/routes/api.py`** & **`server/services/projectService.ts`**
  - **Updates:** Refactored the core project save handlers (both in Python and Node modules) to safely separate any pre-existing `.json` file extension from the raw input before performing character sanitization. This fixes edge cases where saving an existing project implicitly generated duplicate mutated files (e.g., `my_projectjson.json` and `my_project.json`). The updated logic strips `.json`, preserves valid characters (alphanumeric, dashes, underscores), and statically appends exactly one `.json` extension, ensuring that existing projects overwrite cleanly without duplication.
- **`src/App.tsx`**
  - **Updates:** Realigned the frontend state trackers (`handleSaveProject`, `handleLoadProject`) to consume the dynamically sanitized filename explicitly returned by the backend. The UI state hooks (`setCurrentProjectName`) now correctly strip `.json` and sync seamlessly with the physical disk record, avoiding state mismatches across rapid save operations.

## Enriched Project Metadata & List Rendering
- **`backend/routes/api.py`** & **`server/services/projectService.ts`**
  - **Updates:** Re-engineered the `list_projects` (Python) and `listProjects` (Node) functions. Instead of a flat list of filenames, the endpoints now calculate and return detailed metadata objects containing `filename`, a cleanly derived `display_name`, `mtime` (ISO formatted last-modified timestamp), and `size` in bytes. The array is pre-sorted on the server by `mtime` descending, placing the most recently updated projects at the top.
- **`src/components/ProjectModals.tsx`** & **`src/App.tsx`**
  - **Updates:** Updated the frontend interfaces and data mapping hooks to accept the enriched `ProjectMetadata` payload while retaining backward compatibility. Transformed the `LoadProjectModal` row items to visually display the `display_name` stacked cleanly above a `dateStr • sizeStr` human-readable secondary text row. `App.tsx` scene dropdowns and references map gracefully to the objects extracting just the `filename` as needed.

## Filename Case Normalization & Duplicate Prevention
- **`backend/utils/file_handlers.py`** & **`server/services/projectService.ts`**
  - **Updates:** Standardized the casing strategy globally by establishing a single deterministic `sanitize_project_name` (Python) / `sanitizeProjectName` (Node) utility. These functions enforce `.lower()` or `.toLowerCase()` on all raw project identifiers prior to replacing characters. This actively eliminates the creation of duplicate files caused by case inconsistencies (e.g., `scene_jjjal.json` versus `scene_JJjal.json`) on Linux filesystems, ensuring a single normalized target is written to disk.
- **`src/App.tsx`** & Backend Handlers
  - **Updates:** Ensured the authoritative, sanitized filename (returned by the backend upon save) is cached verbatim within the frontend `currentProjectName` state. All subsequent auto-saves, scene staging payloads, and manual edits strictly inherit and transmit this exact filename, preventing diverging variants and seamlessly overwriting the physical JSON file.

## Scene-Driven Storage Hierarchy
- **`backend/routes/api.py`** & **`server/services/projectService.ts`**
  - **Updates:** Refactored project configuration persistence to store each project JSON directly inside its localized scene directory (e.g., `assets/{scene_name}/{scene_name}.json`) instead of a flat project_jsons folder. Updated the `list_projects` / `listProjects` endpoints to aggressively scan nested scene folders within `ASSETS_DIR`, falling back to `PROJECTS_DIR` for backward compatibility. Retrieve, Save, and Delete routes now accurately resolve against these nested scene structures, automatically provisioning subdirectories upon Save, and cleanly clearing JSONs upon Delete. 
- **`src/components/ProjectModals.tsx`**
  - **Updates:** Hardened the `LoadProjectModal` delete logic to actively re-fetch and strictly refresh the local list state upon deletion, preventing any ghost UI entries or cached case-mismatch UI states.
