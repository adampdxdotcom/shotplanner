# File Breakdown & Architecture Roles

## Backend Services & Python Route Handlers (Scene-First Storage)
- **`backend/routes/api.py`**
  - **Role:** Main FastAPI entry point serving the orchestration endpoints (`/api/workflow/stage`, `/api/projects`, `/api/workflows/parse`, etc). 
  - **Updates:** Now utilizes `find_asset_file_path` for unified cross-tier asset lookups when transferring resources via SSH, validating project files, or generating project export ZIP packages. Explicitly parses `scene_name` across endpoints to support the localized `assets/{scene_name}/{media_type}/` hierarchy.

- **`backend/utils/file_handlers.py`**
  - **Role:** File operations and string normalization module.
  - **Updates:** Houses the core `find_asset_file_path` resolution utility which scans active scene subdirectories before falling back to legacy flat directories. Provides `get_scene_directories` to yield fully provisioned absolute paths on demand, guaranteeing folder existence prior to writes. Implements `format_scene_folder_name` to clean untrusted metadata inputs (e.g. standardizing "Scene 1" -> "scene01").

## Node.js Express Server Middlewares (Uploads & Assets)
- **`server/config/constants.ts`**
  - **Role:** Configuration globals.
  - **Updates:** Establishes the `assets/` schema constants alongside the legacy ones, exporting dynamic lookup utilities to bind the new structures.

- **`server/services/assetService.ts`**
  - **Role:** Handles multipart form uploads (single and chunked), maintains the active registry state, and bridges frontend requests to disk storage.
  - **Updates:** Refactored `getAssetFilePath` to match Python's two-tier Scene-First resolution. Modified `handleSingleFileUpload` and `handleChunkUpload` to intercept `scene_name` metadata, dynamically calculating the destination write stream path (`assets/{scene_name}/{media_type}/{filename}`).

- **`server/routes/assetRoutes.ts`**
  - **Role:** Express route controllers for `/api/assets/*`.
  - **Updates:** `serveAssetFile` strictly pipes files using `assetService.getAssetFilePath`, granting it the ability to seamlessly serve blobs across the localized or legacy hierarchies.

- **`server/routes/workflowRoutes.ts`**
  - **Role:** Express route controllers for `/api/workflows/*`.
  - **Updates:** Extracts `scene_name` during the upload of ComfyUI JSON templates to direct them into the specific `assets/{scene_name}/workflows/` directory.

## React Frontend Components (Metadata Binding)
- **`src/App.tsx`**
  - **Role:** Main application orchestrator mounting all contextual tabs and dispatching global API queries.
  - **Updates:** Assures that `scene_name` metadata is bound and piped properly into `WorkflowSection`, `GallerySection`, and `AssetManagerSection`. Passes active `scene_name` to `/api/workflows/parse` to guarantee accurate ComfyUI JSON discovery.

- **`src/components/AssetManagerSection.tsx`**
  - **Role:** Core Shot-Level media planning panel.
  - **Updates:** Enforces explicit injection of `scene_name` into the active `FormData` payload when uploading or editing assets, confirming files are properly routed to their respective contextual folder blocks rather than an orphaned flat directory.

- **`src/components/GallerySection.tsx`**
  - **Role:** Global library browser and bulk uploader interface.
  - **Updates:** Incorporates `sceneName` fallback prop to correctly decorate `FormData` payloads during recursive batch uploads (`runBulkUpload`).

- **`src/components/WorkflowSection.tsx`**
  - **Role:** Pipeline graph manager supporting workflow staging and dynamic media overrides.
  - **Updates:** Assures uploaded ComfyUI `.json` templates submit the active `scene_name` to guarantee the template is correctly nested inside `assets/{scene_name}/workflows/`.

## Project Persistence Extensions
- **`server/services/projectService.ts`** & **`backend/routes/api.py`**
  - **Role:** Handles saving, loading, and importing `project.json` payloads.
  - **Updates:** Automatically intercepts and inspects incoming project data to extract the nested `scene_name` metadata. Invokes the `ensureSceneDirectories` subroutine to recursively provision all Scene-First storage folders immediately upon creation, saving, fetching, or importing of a project. Ensures isolated `assets/{scene_name}/*` sandboxes are physically available before media starts rolling in.

  - **Updates:** 
    - **Project Export (`/projects/{filename}/export`):** Updated the project ZIP export endpoint to exclusively use the unified asset file resolver.     - **SSH & Staging Endpoints (`/assets/sync_remote`, `/workflow/stage`, `/execute`):** Updated the SSH asset transfer, scene staging, and master execution endpoints. They now resolve local asset files using the unified file locator prior to dispatching them via SFTP to the remote ComfyUI input directory on RunPod, preventing "file not found" errors during complex staging tasks.
    - **Project Import (`/projects/import`):** Refactored the ZIP import endpoint using a two-pass mechanism. It now reads the project JSON metadata and `assets_db.json` first, determines the active scene name, provisions the correct directories via `ensure_scene_directories`, and subsequently extracts all workflows and uploads directly into their proper contextual scene subdirectories rather than indiscriminately dumping them into legacy flat folders.

## Settings & Model Connection Verification Endpoints
- **`server/routes/settingsRoutes.ts`**
  - **`POST /api/settings/test-gemini`**: Validates Google Gemini API key configuration by accepting an optional `api_key` payload or falling back to the saved server configuration key via `getStoredGeminiKey()`. Returns an explicit 400 error stating no Gemini API key is configured if neither is present. Dispatches a lightweight verification query using the `@google/genai` client strictly configured with `gemini-3.7-flash` and returns status confirmation alongside active model metadata on success or caught authentication/network error details on failure.
  - **`POST /api/settings/test-lm-studio`**: Tests connectivity to local LM Studio server endpoints (`GET /v1/models`) using an asynchronous HTTP client with a 5-second `AbortController` timeout. On success, returns confirmation payloads containing loaded model counts and model names. On failure (connection refused, unreachable host, timeout), catches network exceptions and returns a clear failure description.

## Python FastAPI Backend Settings & Headshot Endpoints
- **`backend/routes/prompt_routes.py`**
  - **`POST /api/settings/test-lm-studio`**: Accepts target URL payloads (`url`, `lm_studio_url`, or `endpoint`). Logs `[LM Studio Test] Testing reachability for URL: {url}` to terminal, queries `{url}/models` asynchronously via `httpx.AsyncClient` with a 5s timeout, logs success `[LM Studio Test] Success (HTTP {status}) - Found {count} models: {model_names}` or failure `[LM Studio Test] Failed to connect to {url}: {error_message}`, and returns the corresponding response.
  - **`POST /api/settings/test-gemini`**: Accepts an optional API key or falls back to `assets/gemini_config.json`. Logs `[Gemini Test] Validating API key...`. If missing, logs and returns a 400 error. Validates via Gemini REST API `generateContent` using `httpx.AsyncClient` and strictly targeting `gemini-3.7-flash`, logs success `[Gemini Test] Verified successfully with model gemini-3.7-flash` or failure `[Gemini Test] Validation failed: {error}`, and returns status payload.
- **`backend/services/llm_service.py`**
  - Configured prompt expansion routines to default strictly to `gemini-3.7-flash` for all Gemini-backed synthesis operations.
- **`backend/routes/headshot_routes.py`**
  - **`POST /api/headshots/generate`**: FastAPI route handling character headshot variation requests. Parses JSON or Form Data parameters, supports `imageBase64`, `existingAssetFilename`, and `activeSceneName`, calls `generate_headshots()`, and returns candidate image objects.
  - **`POST /api/headshots/save-selected`**: Accepts user-approved variation candidates, decodes base64 payloads, invokes `save_selected_headshots()` targeting the active scene directory, and returns saved asset records.
- **`backend/services/headshot_service.py`**
  - Defines `HEADSHOT_TEMPLATES` for character visual presets ("Facing", "3/4 Profile", "Full Profile", "Cinematic / Mood").

## Civitai Metadata Resolver & AIR Parser Version-First Architecture
- **`server/services/civitaiService.ts` & `backend/services/civitai_service.py`**
  - Updated `parseCivitaiQuery` (and `parse_civitai_query` in Python) to strictly prioritize Model Version ID across all input formats:
    1. **Civitai AIR Parser**: Extracts strictly the numeric digits located between `@` and `+` (or end of string/whitespace) (e.g., `urn:air:minimaxh3:diffusionmodel:civitai:2830065@3193337+3074134` -> `version_id: 3193337`, `model_id: 2830065`), discarding trailing `+` suffixes and hash numbers.
    2. **URL & Query Parser**: If a URL contains a `modelVersionId` query parameter (e.g. `?modelVersionId=3193337`), prioritizes that version ID over the parent model path.
    3. **Raw Numeric ID**: Flags raw numeric IDs (e.g. `3193337`) so the resolver queries the Civitai Model Version endpoint (`https://civitai.com/api/v1/model-versions/{id}`) first.
  - Updated `fetchCivitaiModelInfo` (and `fetch_civitai_model_info` in Python):
    1. Queries `https://civitai.com/api/v1/model-versions/{modelVersionId}` first to ensure the response contains the exact version title, files list, base model architecture, and authenticated download URL for that specific release.
    2. Enriches version metadata by querying the parent model endpoint (`https://civitai.com/api/v1/models/{modelId}`) for categories, commercial use permissions, tags, and all available version options.
    3. Seamlessly falls back to the Model endpoint if a raw ID was a Model ID instead of a Version ID.
- **`src/types.ts`**
  - Added `files?: any[]` to `CivitaiModelMetadata` interface to carry the version's complete files list to the client.

  - **`executeUnifiedRemoteDownload` / `execute_unified_remote_download`**: Updated the unified remote execution pipeline to execute using `curl` exclusively.

## Chroma-Key Background Removal & Actor Pose Staging Pipeline
- **`src/utils/chromaKey.ts`**
  - **Role:** High-performance client-side Chroma-Key and background removal utility for the staging pipeline.
  - **Core Logic & Performance:**
    - Uses an in-memory 2D `<canvas>` with `{ willReadFrequently: true }` to optimize raw `Uint8ClampedArray` pixel manipulation.
    - **`autoDetectKeyColor(imageElement)`**: Intelligently samples corner pixels and center-edge borders, auto-detecting standard chroma green (`#00FF00`) or the dominant solid backdrop color.
    - **`samplePixelColor(imageElement, x, y)`**: Helper to extract RGB hex values at specific coordinates for color eyedropper sampling.
    - **`applyChromaKey(imageElement, options)`**: Performs Euclidean distance calculations in RGB color space against the target key color. Includes a configurable tolerance threshold, smooth feathering edge softness band, and an automated despill pass to eliminate color halos and fringing on semi-transparent silhouette edges.
    - Outputs processed cutouts directly as clean transparent PNG data URLs (`image/png`).
- **`src/components/cast/ActorPoseKeyingPanel.tsx`**
  - **Role:** Interactive actor pose selection, reference filtering, dropzone upload, and real-time Chroma-Key inspector.
  - **Features:**
    - **Character Selector Dropdown**: Allows choosing any actor from the project cast.
    - **Filtered Reference Gallery**: Automatically filters character reference images prioritizing `Pose (Staging / Cutout)` or `Body Reference` types, with one-click selection.
    - **Quick Dropzone Upload**: Supports drag-and-drop or manual file selection to upload a new pose photo on the fly with automatic tag enrichment.
    - **Keying Inspector & Eyedropper**:
      - Live transparent cutout preview rendered over a high-contrast dark checkerboard grid (`8px` tiles).
      - Color Eyedropper tool to click anywhere on the source image to sample and set the key color in real time.
      - Preset color chips (Chroma Green, Chroma Blue, Studio Magenta, Studio White, Studio Black).
      - Instantaneous real-time sliders for **Tolerance / Threshold** (sensitivity) and **Edge Softness** (feathering).
      - Invert Key toggle to handle inverted or subject-isolated masks.
    - **Confirmation Action ("Add Posed Actor to Stage")**: Processes the keyed cutout and emits the transparent actor data to the staging session.
- **`src/components/cast/AiReferenceStagingStudioModal.tsx`**

- **`src/utils/compositeCanvasExport.ts`**
  - **Role:** High-performance client-side composite image rendering utility for the staging workspace.
  - **Core Logic:**
    - **`renderCompositeToBlob(options)`**: Flattens the background environment plate and all layered actor cutouts into a single high-resolution transparent/opaque PNG image (`Blob`).
    - Handles active aspect ratio dimensions (e.g. 1920x1080 for 16:9, 1920x803 for 2.39:1, 1440x1080 for 4:3, 1080x1920 for 9:16).
    - Draws the location asset image or custom background plate with aspect-ratio-preserving cover fit, falling back to a subtle studio grid on dark canvas if no environment plate is chosen.
    - Accurately renders each staged actor sorted by `zIndex`:
      - Handles horizontal mirroring (`scale(-1, 1)`) when `isFlipped` is active.
      - Projects actor positioning based on `xPercent` and `yPercent`.
      - Adds a natural ground contact elliptical shadow under the feet of cutouts to ground the actors within the environment.
      - Renders circular avatar portraits with initials or headshots if no transparent cutout is available.
