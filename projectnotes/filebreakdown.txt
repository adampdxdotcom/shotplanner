# File Breakdown & Architecture Roles

## Backend Services & Python Route Handlers (Scene-First Storage)
- **`backend/routes/api.py`**
  - **Role:** Main FastAPI entry point serving the orchestration endpoints (`/api/workflow/stage`, `/api/projects`, `/api/workflows/parse`, etc). 
  - **Updates:** Now utilizes `find_asset_file_path` for unified cross-tier asset lookups when transferring resources via SSH, validating project files, or generating project export ZIP packages. Explicitly parses `scene_name` across endpoints to support the localized `assets/{scene_name}/{media_type}/` hierarchy.

- **`backend/utils/file_handlers.py`**
  - **Role:** File operations and string normalization module.
  - **Updates:** Houses the core `find_asset_file_path` resolution utility which scans active scene subdirectories before falling back to legacy flat directories. Provides `get_scene_directories` to yield fully provisioned absolute paths on demand, guaranteeing folder existence prior to writes. Implements `format_scene_folder_name` to clean untrusted metadata inputs (e.g. standardizing "Scene 1" -> "scene01").

## Node.js Express Server Middlewares (Uploads & Assets)
- **`server/config/constants.ts`**
  - **Role:** Configuration globals.
  - **Updates:** Establishes the `assets/` schema constants alongside the legacy ones, exporting dynamic lookup utilities to bind the new structures.

- **`server/services/assetService.ts`**
  - **Role:** Handles multipart form uploads (single and chunked), maintains the active registry state, and bridges frontend requests to disk storage.
  - **Updates:** Refactored `getAssetFilePath` to match Python's two-tier Scene-First resolution. Modified `handleSingleFileUpload` and `handleChunkUpload` to intercept `scene_name` metadata, dynamically calculating the destination write stream path (`assets/{scene_name}/{media_type}/{filename}`).

- **`server/routes/assetRoutes.ts`**
  - **Role:** Express route controllers for `/api/assets/*`.
  - **Updates:** `serveAssetFile` strictly pipes files using `assetService.getAssetFilePath`, granting it the ability to seamlessly serve blobs across the localized or legacy hierarchies.

- **`server/routes/workflowRoutes.ts`**
  - **Role:** Express route controllers for `/api/workflows/*`.
  - **Updates:** Extracts `scene_name` during the upload of ComfyUI JSON templates to direct them into the specific `assets/{scene_name}/workflows/` directory.

## React Frontend Components (Metadata Binding)
- **`src/App.tsx`**
  - **Role:** Main application orchestrator mounting all contextual tabs and dispatching global API queries.
  - **Updates:** Assures that `scene_name` metadata is bound and piped properly into `WorkflowSection`, `GallerySection`, and `AssetManagerSection`. Passes active `scene_name` to `/api/workflows/parse` to guarantee accurate ComfyUI JSON discovery.

- **`src/components/AssetManagerSection.tsx`**
  - **Role:** Core Shot-Level media planning panel.
  - **Updates:** Enforces explicit injection of `scene_name` into the active `FormData` payload when uploading or editing assets, confirming files are properly routed to their respective contextual folder blocks rather than an orphaned flat directory.

- **`src/components/GallerySection.tsx`**
  - **Role:** Global library browser and bulk uploader interface.
  - **Updates:** Incorporates `sceneName` fallback prop to correctly decorate `FormData` payloads during recursive batch uploads (`runBulkUpload`).

- **`src/components/WorkflowSection.tsx`**
  - **Role:** Pipeline graph manager supporting workflow staging and dynamic media overrides.
  - **Updates:** Assures uploaded ComfyUI `.json` templates submit the active `scene_name` to guarantee the template is correctly nested inside `assets/{scene_name}/workflows/`.

## Project Persistence Extensions
- **`server/services/projectService.ts`** & **`backend/routes/api.py`**

Invokes the `ensureSceneDirectories` subroutine to recursively provision all Scene-First storage folders immediately upon creation, saving, fetching, or importing of a project. Ensures isolated `assets/{scene_name}/*` sandboxes are physically available before media starts rolling in.

It now reads the project JSON metadata and `assets_db.json` first, determines the active scene name, provisions the correct directories via `ensure_scene_directories`, and subsequently extracts all workflows and uploads directly into their proper contextual scene subdirectories rather than indiscriminately dumping them into legacy flat folders.

  - Defined the unified `ShotTake` interface holding: `id` (string), `take_number` (number), `created_at` (ISO timestamp), `video_url` (optional string), `video_filename` (optional string), `expanded_prompt` (string), `generation_params` (steps, megapixels, frames), `is_hero` (boolean), and optional QA review metadata.
  - Updated `ShotItem` to support `takes: ShotTake[]`, `hero_take_id?: string`, and `active_take_id?: string` with safe default empty arrays.
- **`backend/routes/execution_routes.py` & `backend/services/workflow/builder.py` & `backend/services/execution_service.py`**
  - Pydantic models and execution builders calculate the sequential take number (`take_number = len(shot.takes) + 1`) for any executed or re-rendered shot.
  - Systematically formatted output video prefix and expected filenames using `{scene_name}_Shot_{shot_number}_Take_{take_number}.mp4`.
  - Returned `expected_video_filename` and `take_number` in staging and execution responses.
- **`server/services/executionService.ts` & `src/utils/formatters.ts` & `server/utils/formatters.ts`**
  - Updated Node.js execution pipeline and `generateSaveVideoPrefix` to format filenames with take numbers.
- **`src/components/TakeSelector.tsx` & `src/components/TakeReviewModal.tsx` & `src/components/RendersView.tsx`**
  - Integrated take selector pill components allowing instant switching between versions, marking hero takes (⭐), and reviewing QA metadata.
  - Implemented the full Take Review Modal with streaming video playback, parameter comparisons, and hero take promotion.
- **`server/services/projectService.ts` & `backend/services/project_service.py`**
  - Verified and confirmed that project persistence (saving, loading, exporting ZIP archives) completely preserves the `takes` array, `hero_take_id`, and `active_take_id` without data loss.

## Dynamic Live Pre-Generation Context Preview Architecture
- **`src/utils/formatters.ts` & `src/types.ts`**
  - Created `buildSubjectDefinitions` to systematically synthesize structured multimodal subject tags and media labels (`<Picture N>`, `<Video N>`, `<Audio N>`) for character bibles and location reference slots.
  - Implemented `computePrePromptContext` to calculate a real-time pre-prompt context string fusing:
    1. Scene and Shot Planning Header with optics and framing (`Shot {num} - {type} - {lens} - {movement} - {aspect}`).
    2. Global Subject Definitions formatted for reference asset mapping.
    3. Framing Directives (OTS angle, anchor/focus subjects, side positioning).
    4. Scene Reference and Single Subject identity preservation constraints.
    5. Active Concept / Stub description with default placeholder guidance.
    6. Overall soundscape and non-diegetic music footer specifications.
- **`src/components/LLMSection.tsx`**
  - Implemented dynamic live pre-prompt context display inside the Prompt expansion tab's "Preview / Edit Expanded Prompt" textarea whenever `expandedPrompt` is blank or ungenerated.
  - Wired reactive recalculation of the live preview context whenever camera dropdowns, lens, aspect ratio, OTS framing parameters, mapped asset slots, or concept stubs are tweaked.
  - Added visual status badges differentiating "Live Pre-Prompt Context" (with subtle active pulse) from "Compiled / Custom Prompt".
  - Added a "Reset to Live Preview" action allowing users to clear custom manual edits and re-engage real-time synthesized context preview.
  - Updated clipboard copying to dynamically copy the active live pre-prompt context when in preview mode or the compiled prompt when generated/edited.
  - Ensured "Generate Prompt with LM Studio / Gemini" completely overwrites the preview textarea with the finalized assembled prompt (Header + LLM Description + Footer), marks the project dirty, and auto-saves to shot state.
- **`src/components/hub/PromptEngineeringPanel.tsx`**
  - Integrated `computePrePromptContext` into the Scene Project Hub's Prompt Engineering panel to display the real-time synthesized pre-prompt context and provide "Reset to Preview" controls.
